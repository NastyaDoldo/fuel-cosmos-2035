# Топливный космоконтур 2035 — цифровой контур планирования

Учебный инструмент планирования снабжения орбитального топливного узла на 2035–2040 гг.
(кейс КосмоХакатон 2026). Расчётное ядро считает материальный баланс, экономику,
ограничения и стресс-тесты; интерфейс оператора задаёт решения и показывает результат.

Это **не** система управления реальным оборудованием/телеметрией.

## Быстрый старт

Требования: Python 3.10+ (проверено на 3.12).

```powershell
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
```

### CLI (расчёт + выгрузки)

```powershell
python -m fuelloop.cli run                          # standard + stress, выгрузка в results/
python -m fuelloop.cli run --risks --sensitivity --monte-carlo
python -m fuelloop.cli run --scenarios standard,stress,custom_geopolitics
python -m fuelloop.cli run --plan configs/plan_standard.json --out results
```

### Интерфейс оператора (Streamlit)

```powershell
streamlit run src/fuelloop/app/dashboard.py
```

Порядок проверки решения:

1. **Тесты**: `python -m pytest -q` (27 тестов: контрольный пример, границы, невыполнимые планы, стресс, риски, выгрузки)
2. **Стандартный сценарий**: `python -m fuelloop.cli run` → `results/plan_standard.csv` — все проверки зелёные, обслуживание 100%
3. **Обязательный стресс**: `results/plan_stress.csv` — дефицит 151,1 т (2038–2040) показан честно, без корректировок задним числом
4. **Доп. тесты**: `--risks --sensitivity --monte-carlo` (Монте-Карло: n=1000, seed=42)
5. **Сравнение и выгрузка**: `results/scenario_comparison.csv`, `results/fuelloop_results.xlsx`

```

    scenarios.py    сценарный слой: изменения применяются к копии данных

    engine.py       оркестратор: план × сценарий → результаты по годам
    risks.py        реестр рисков, чувствительность, Монте-Карло
  io_layer/
    exporters.py    выгрузка CSV/XLSX
  app/
    dashboard.py    Streamlit-рабочее место оператора
  cli.py           командная строка
data/             входные данные (JSON/CSV) — не захардкожены в коде

```

## Ключевые правила расчёта (как в кейсе)

- Материальный баланс: `Запас на конец = Запас на начало + Поступление − Потери − Выдача`; потери один раз от throughput
- Помесячные шаги (12/год, 365 дней): проверки запаса/ёмкости на каждом шаге; дефицит отдельно, запас не уходит в минус
- 45-дневный резерв: `R = спрос года × 45/365`, проверка на начало каждого года; альтернатива — законтрактованный резерв E (42 дня активации ≤ 45)
- Платежи: переменный = цена × max(отбор, ToP × резерв); резервный = тариф × резерв; ToP не удваивается
- Потери: 4,5% до ZBO, 1,2% после; хранение 0,72 млн/т-год по средневзвешенному запасу
- NPV расходов: реальная ставка 10%, дисконтирование на середину года платежа
- Надёжность каналов **не** умножает объёмы в стандартном сценарии — она в реестре рисков
- В стрессе недопоставка ISRU не возвращает платежей; 99/97% — ориентиры, дефицит показывается как есть
- Emergency нельзя базовым каналом >2 лет подряд — проверяется автоматически

## Базовый план (baseline_v1) и результаты

A Earth-Core как основа + буферы B; ZBO (оплата 2036, ввод 2037); Lunar-ISRU
(CAPEX 625+625 в 2036–2037, ввод 2038); E — резерв с 2038. Стартовый запас
12,33 т (45 дней спроса 2035) закуплен у B, оплата t=0.

| Сценарий | NPV, млн | CAPEX, млн | Дефицит, т | Мин. обслуживание |
|---|---|---|---|---|
| Стандарт | 8023 | 1430 | 0 | 100% / 100% крит. |
| Стресс | 8419 | 1430 | 151,1 | 81,3% / 100% крит. |

Сравнение альтернатив (см. `scripts/alternatives.py`): без ISRU план невыполним
(обслуживание 65,8%); Earth-New (C) вместо ISRU даёт NPV 8017 при CAPEX 540 и
лучше держит стресс (87% против 81,3%) — но ISRU дешевле в эксплуатации
(3,0 против 7,1 млн/т) с 2039.

## Тесты

```powershell
python -m pytest -q
```

- Независимый ручной контрольный пример (числа посчитаны вручную, `tests/test_manual_control.py`)
- Граничные случаи: нулевой спрос/запас, превышение мощности, переполнение хранилища
- Невыполнимые планы: E базовым каналом 3 года подряд, CAPEX > 1800, ISRU без финансирования, пустой план — всё помечается нарушениями
- Стресс: мультипликаторы применяются, ISRU-недопоставка без возврата платежей, потери ≤ 2% только с ZBO
- Чувствительность и Монте-Карло (seed=42, воспроизводимо)
